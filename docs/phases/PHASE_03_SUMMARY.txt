================================================================================
PHASE 3 SUMMARY: Authentication & JWT Setup
================================================================================

1. WHAT WAS IMPLEMENTED IN THIS STEP
--------------------------------------------------------------------------------
- Installed security packages: `bcryptjs` (for password hashing) and `jsonwebtoken` (for creating login tokens).
- Created a utility file (`utils/generateToken.js`) to generate a digital "ID badge" for users.
- Created `authController.js` which contains the logic for Registering a new user and Logging in an existing user.
- Created `authRoutes.js` and wired it to our main `server.js` so our API is accessible at `/api/auth`.
- Updated `.env` with a secret key for tokens.

2. WHY THIS STEP IS IMPORTANT
--------------------------------------------------------------------------------
Security is critical. If we store passwords as plain text (e.g., "password123"), anyone who hacks the database can read them. Hashing turns them into an unreadable scramble. Furthermore, we need a way to remember that a user is logged in without asking for their password on every single request. JWT tokens solve this perfectly.

3. HOW IT WORKS (SIMPLE EXPLANATION)
--------------------------------------------------------------------------------
- Register: When you sign up, the backend takes your password, runs it through a complex math formula (bcrypt) to scramble it, and saves the scrambled version. It then gives you a JWT Token (a temporary digital ID badge).
- Login: When you log in, the backend takes the password you just typed, scrambles it using the same math formula, and checks if it matches the scrambled password in the database. If it does, you get a new Token.
- The Token: You attach this token to future requests. The backend looks at the token, verifies it using our `JWT_SECRET`, and says, "Ah, I know who you are, come on in."

4. KEY CONCEPTS USED
--------------------------------------------------------------------------------
- bcryptjs (Hashing & Salting): "Hashing" scrambles the password. "Salting" adds random data before scrambling, making it immune to pre-calculated attacks.
- JWT (JSON Web Token): A secure string of characters that represents the user. It expires after a set time (e.g., 30 days) to prevent old stolen badges from working forever.
- Express router (`express.Router()`): A way to organize our URLs neatly instead of putting everything into `server.js`.

5. COMMON MISTAKES TO AVOID
--------------------------------------------------------------------------------
- Forgetting to "await" bcrypt: Hashing takes time. If you forget `await`, the code moves on before the password is ready, causing crashes.
- Exposing the JWT_SECRET: Your secret key must stay in the `.env` file and NEVER be pushed to GitHub. If someone gets your secret key, they can forge fake ID badges!
- Sending passwords back: Notice that in the register/login response, we send the `name`, `email`, and `token`, but NEVER send the `password` back to the frontend.

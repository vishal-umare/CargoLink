================================================================================
PHASE 2 SUMMARY: Mongoose Models Creation
================================================================================

1. WHAT WAS IMPLEMENTED IN THIS STEP
--------------------------------------------------------------------------------
Three database models (schemas) were created using Mongoose:
- User Model: Stores information for drivers, shippers, and admins.
- Load Model: Stores details about a shipment (pickup, delivery, weight).
- Booking Model: Links a driver and a load together when a job is accepted.

2. WHY THIS STEP IS IMPORTANT
--------------------------------------------------------------------------------
MongoDB is a "NoSQL" database, meaning it doesn't have strict tables like SQL databases do. Mongoose adds a strict "Schema" (a blueprint) to MongoDB so we can control exactly what kind of data is saved. For example, ensuring that a "weight" is always a number, and an "email" is properly formatted. This prevents bad data from breaking the app.

3. HOW IT WORKS (SIMPLE EXPLANATION)
--------------------------------------------------------------------------------
Think of a Mongoose model as a form template. 
- When a new user registers, the data is pushed through the `User` template. 
- If they forget to include their name, or their email is invalid, the template rejects it and throws an error automatically. 
- We also used "References" (`ObjectId`). Instead of copying all of a user's information into a load, the Load model just saves the user's unique ID (`shipperId`). This connects the two pieces of data efficiently.

4. KEY CONCEPTS USED
--------------------------------------------------------------------------------
- mongoose.Schema: The function used to define the blueprint for our data.
- Validation: Rules like `required: true` and `unique: true` that enforce data integrity.
- Enums: A rule that restricts a field to specific words. For example, a role can ONLY be 'driver', 'shipper', or 'admin'.
- Timestamps: Setting `{ timestamps: true }` automatically records exactly when data is created (`createdAt`) or modified (`updatedAt`).
- References (ref): Linking one model to another (like linking a Load to a User).

5. COMMON MISTAKES TO AVOID
--------------------------------------------------------------------------------
- Forgetting `module.exports`: If you don't export the model, your other files won't be able to find or use it!
- Missing 'ref' in ObjectIds: When storing another model's ID, always include `ref: 'ModelName'` so Mongoose knows where to look it up later.
- Case Sensitivity: Making typos in Enum values (e.g., saving "Driver" with a capital D when the enum only allows lowercase "driver").

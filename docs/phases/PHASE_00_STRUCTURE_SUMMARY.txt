2. WHY THIS STEP IS IMPORTANT
--------------------------------------------------------------------------------
When building a full-stack application, mixing frontend and backend dependencies in the same `package.json` and root directory causes massive headaches. 
- Dependency Conflicts: Node.js packages can conflict with React browser packages.
- Deployment: Services like Vercel (for frontend) and Render/Heroku (for backend) need clear boundaries so they know exactly which folder to build.
- Readability: It is now immediately obvious to any developer looking at the project that there are two distinct halves: a frontend and a backend.

3. HOW IT WORKS (SIMPLE EXPLANATION)
--------------------------------------------------------------------------------
The project is now a "Monorepo" (a single repository containing multiple isolated projects).
- To work on the website UI, you open a terminal, `cd frontend`, and run `npm run dev`. This runs the React app on port 8080.
- To work on the database/API, you open a separate terminal, `cd backend`, and run `npm start`. This runs the Node server on port 5000.
- They talk to each other over the network via HTTP requests (`fetch`), exactly as if they were running on completely different computers.

4. KEY CONCEPTS USED
--------------------------------------------------------------------------------
- Separation of Concerns: A fundamental computer science principle. The frontend should only care about UI, and the backend should only care about data. Their physical folder structure now reflects this logical separation.
- Monorepo Structure: Housing multiple related projects inside one parent folder for easier management.

5. COMMON MISTAKES TO AVOID
--------------------------------------------------------------------------------
- Running commands in the wrong folder: If you try to run `npm install axios` in the root folder, it will create a new `package.json` there. You MUST be inside the `frontend` or `backend` folder before running `npm` commands.
- Incorrect relative paths: If your frontend used to reference a file outside of its `src` folder, those paths might break. By moving the entire frontend ecosystem together, we avoided breaking internal relative paths.

2. KEY FEATURES IMPLEMENTED
--------------------------------------------------------------------------------
A) IMPROVED BOOKING SYSTEM (STRICT BACKEND VALIDATION)
   - The driver accept route now uses an atomic query: `findOneAndUpdate({ _id: id, status: 'open' }, ...)`
   - This physically prevents two drivers from accepting the exact same load simultaneously. The second driver receives: "Load is no longer available — it may have been accepted by another driver".
   - Status transitions are strictly enforced:
     open → assigned → in_transit → delivered

B) DRIVER DASHBOARD (MATCHES)
   - "Available Loads" tab shows only strictly 'open' loads.
   - "My Loads" tab shows loads that are 'assigned' or 'in_transit'.
   - Completed loads are available in the "Trip History" tab.

C) STATUS TRANSITIONS & UI
   - When a load is assigned, it displays a "Start Trip" button.
   - Clicking "Start Trip" moves it to 'in_transit', updates the badge to "🚛 In Transit", and changes the button to "End Trip — Mark as Delivered".
   - Badges in `LoadCard` render dynamic styles for all states (Emerald for open, Blue for assigned, Amber for in_transit, Purple for delivered).
   - Instant UI feedback via optimistic React Query invalidation across all tabs.

D) EDGE CASES HANDLED
   - Duplicate bookings physically blocked at the database level.
   - Other drivers cannot mark a trip as complete (401 Unauthorized if assigned_driver_id mismatches).
   - Shippers cannot delete a load while the driver is 'in_transit'.
